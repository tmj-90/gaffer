## [Unreleased]

### Added

- **117 skills, a lint gate for every one, and role-aware forwarding.** The skill library grows from 69 to 117: build packs the delivery agent was missing (`fix-bug` with reproduce-first regression tests, `debug-failing-ci`, `dependency-upgrade`, `deprecate-and-remove`, `add-feature-flag`, `add-config-option`, `add-cli-command`, `error-handling`, `structured-logging-and-tracing`, `performance-profiling`, `concurrency-and-async`, `background-jobs`, `scheduled-jobs`, `caching-strategy`, `rate-limiting`, `idempotency-and-retries`, `pagination-and-filtering`, `api-versioning`, `openapi-contract`, `outbound-webhooks`, `auth-session-and-oauth`, `file-uploads`, `sql-query-performance`, `data-privacy`, `event-driven-messaging`, `write-adr`, `shell-scripting`), frontend packs (`react-patterns`, state management, forms and validation, data fetching, performance, testing, `i18n-l10n`), testing packs (`e2e-browser-test`, `contract-test`, `property-based-test`, `test-fixtures-and-factories`), five new language packs (Rust, Kotlin, Swift, C#, Ruby) and five **review lenses** (`security-review`, `performance-review`, `accessibility-review`, `test-quality-review`, `migration-review`) written for a reviewer, each a checklist walked against the code. `runner/test/skills-lint.test.mjs` gates every `SKILL.md`: a trigger-phrased one-line description, a real procedure of at least 220 words, only real dispatch/memory MCP tool names (a skill once named a tool that did not exist and every delivery that followed it silently failed), valid `x` skill cross-references, known area buckets, no duplicates. Selection is now **per agent role**: `select-skills --role review|clarify|test|plan|spec|product|merge|bootstrap|delivery` hands each role its core, its lens areas, the stack's language pack and (where it matters) the surface packs — the reviewer used to get a fixed five and never saw the diff's conventions pack or a security lens; it now does, and its prompt names the lenses. `run-lint` and `run-coverage` were rewritten to the new bar. Documented in `docs/skill-selection-and-stacks.md`.
- **Two new agent lanes.** (1) A **security second-opinion reviewer**: after the primary reviewer approves a high-risk ticket, or one whose diff touches a security-sensitive path (`GAFFER_SECURITY_REVIEW_RE`), a second, independent agent walks the `security-review` checklist against the code; its CHANGES overrides the primary approve with its findings as the rework feedback, a second reviewer that did not run holds the ticket exactly like a primary that did not run, and it never widens the bar (`GAFFER_SECURITY_REVIEW=0` disables it; proven end to end by `runner/test/security-review-lane.test.sh`). (2) The **independent black-box tester is live**: `tester-run.mjs --live` (run by the tick's new tester pass, `runner/lib/tester.sh`, when `GAFFER_TESTING` is on) checks the delivered branch out in a throwaway worktree, mounts the test role's skills, scopes a dispatch MCP server to the ticket so the tester's per-AC notes are accepted without a claim, spawns the tester with the contract-only context (still no pointer to the diff), reads its verdict from an out-of-band `{"verdict":"PASS"|"FAIL"}` token, keeps its tests on `gaffer/ticket-<n>-tests` (the reviewed delivery branch is never rewritten), and records PASS → ready_for_merge / FAIL → refining; no token holds the ticket for a human. Usage is ledgered as `tester` / `security-review`.
- **The idle maintenance lane now closes its loop, and can be switched on from the dashboard.** Three defects kept "an idle factory finds and fixes its own tech debt" from ever being true: (1) idle scans drafted tickets with **no acceptance criterion**, and Dispatch's `ready` gate refuses a criterion-less ticket, so the self-improve promotion always failed; (2) the crew scan loops read repos from crew.yaml's own `repos:` list, which dashboard onboarding never writes, so every dashboard-onboarded factory scanned nothing (`no_repos`); (3) the lane needed `GAFFER_MAINTENANCE=1` in the runner's env, a knob exposed nowhere, on top of crew.yaml's own `loops.maintenance.enabled` and each loop's flag. Now: every idle draft carries the **behaviour-preserving oracle as a real criterion** with the repo's test command as its `check_command`, so the runner verifies it mechanically in the delivery worktree and promotion passes the ready gate (a draft whose criterion cannot be attached is never promoted); crew's `idle` and `maintain` commands **merge Dispatch's repository registry** into the crew repo list (crew.yaml entries still win on a clash; repos without a local path are skipped); crew.yaml's `loops.maintenance.enabled` is the **single switch** — tick.sh asks crew on every idle tick and crew answers `disabled` while it is off, `GAFFER_MAINTENANCE` is only the env override (`0` kill switch, `1` force via `crew maintain --force`, empty = crew.yaml decides). The Settings → **Idle loops** panel gains the maintenance switch, the two lanes it was missing (tech debt, type quality), a "Use recommended set" button, the self-improve gate (opt-in repos, risk ceiling, per-tick cap) and a live status line saying what the next idle tick will do (`GET|PUT /api/idle-loops` carry `maintenance` and `self_improve`). The Work view's **Poll for work** button used to refuse to spawn a tick on an empty queue; with the lane on it now fires the idle tick (`POST /poll-work` answers `idle: "maintenance"`) and says so. Proven end to end: `runner/test/maintenance-e2e.sh` runs the real tick.sh three times against a fixture repo with a planted god-file (draft + oracle + promotion → stub delivery with `runner:check` → dedupe) as its own CI step, and the browser regression drives the same flow through the Settings panel and the Work view's Poll button.
- **Reviewer and clarify passes are routed.** The model router that already picked the delivery tier now also picks the reviewer's (phase `review`, default mid; a high-risk or many-AC ticket climbs, a trivial one does not drop — a wrong APPROVE is the expensive mistake) and the intake clarify pass's (phase `clarify`, default cheap; it files criteria and raises decisions, never code). Both decisions are logged as `ROUTE` lines; explicit `GAFFER_IMPL_MODEL` / `GAFFER_PLAN_MODEL` overrides still win, and the static flags remain the fallback.
- **Hybrid lore retrieval.** `search_lore` / `memory search` now fuse the FTS5 bm25 ranking with a dense vector per record (memory migration 013, `lore_embeddings`), so a typo beside a real term, a joined or split compound (`ratelimiting`, `time out`) or a subword (`argon 2id`) still finds the record that pure keyword matching missed. The built-in embedder is a deterministic hashed n-gram space (word unigrams/bigrams + character trigrams, signed hashing, 256 dims): no model, network or credential, microseconds per record, vectors as portable as the SQLite file. It captures surface similarity, not meaning; a model-backed embedder plugs in behind the same `Embedder` interface and re-embeds lazily under its own `model` id. Fusion is magnitude-preserving (top lexical hit = 1, dense capped at 0.5) so a dense-only near-miss can outrank only a weak keyword hit, and the existing trust re-rank applies unchanged; dense candidates pass the same repo / tag / kind / status filters and a cosine floor keeps a genuinely unknown topic at zero hits (the absence-marker path survives). Every hit carries `retrieval: lexical | dense | both`. Vectors are written with each record and backfilled on the first search of an older database. `MEMORY_HYBRID_RETRIEVAL=0` restores pure bm25. `packages/memory/test/retrieval-eval.test.ts` is the labelled relevance set: hybrid recall is asserted monotone over lexical, each documented blind spot is asserted recovered, and unknown topics are asserted empty.
- **Editable Definition-of-Done gate commands.** The repo detail view now has a test / lint / coverage command editor (`POST /repos/:id/commands`, `dispatch repo set-commands`). Onboarding auto-detects them; a wrong or missing command was the top reason a delivery bounced or shipped unverified, and there was no way to fix it from the dashboard.
- **Self-hosted dashboard fonts.** Space Grotesk and JetBrains Mono (latin, OFL-1.1) are vendored under `assets/fonts/`; the dashboard makes no third-party request on load. `scripts/vendor-fonts.sh` regenerates them.
- **Browser-driven UI regression (opt-in).** `scripts/ui-regression/run.sh` drives the real dashboard end to end with a stub worker: onboard → create ticket → machine-checkable AC → mark ready → Poll for work (live tick) → Review diff + arm/confirm Approve → merge → done → Suggest work → every view → live-stream refresh. Screenshots + `results.json`. Runs in CI as its own `ui-regression` job (ubuntu, pinned Chromium), so the dashboard now has a browser gate on every push and pull request.
- **Machine-checkable acceptance criteria.** An AC may now carry a `check_command` (`dispatch ac add --check '<cmd>'`, `POST /tickets/:id/acceptance-criteria`, MCP `add_acceptance_criterion`). After the DoD gates the **runner** executes each check in the primary delivery worktree (bounded by `GAFFER_DOD_TIMEOUT`) and records the verdict through the trusted `dispatch ac check-result` path: exit 0 ⇒ `satisfied` with `verified_by = runner:check` plus a `test_output` evidence row carrying the exit code and output tail; non-zero ⇒ `failed` and the delivery is auto-rejected to rework with the failing output as feedback, exactly like a failing DoD gate. The done gate (which fires at approval) refuses a checked AC the runner has not passed — an agent marking it satisfied via `record_ac_evidence` does not count. The ticket view's Add-AC form has a "Check command" field. Prose ACs are unchanged. Schema v21 adds the nullable column with a NULL backfill. See `runner/lib/ac-checks.sh`.
- **Human queue surfaces dependents of a cancelled/failed ticket.** Only `done` satisfies a dependency, so a ticket depending on one that was cancelled or failed waited forever with nothing to show for it. `/api/human-queue` now lists it (`dependency_cancelled`) naming the dead dependency and the two remedies: remove the edge or cancel the dependent.
- **Lore version history.** `updateLore` snapshots the pre-update row into `lore_version` (version 1 = the original) before overwriting, so an edit is diffable and reversible; `listLoreVersions(id)` reads the history. Memory migration 012.
- **Live event stream — `GET /api/events/stream?since=<seq>`.** The control plane pushes its append-only `work_events` log as Server-Sent Events (metadata-only, the same safe shape as `/api/activity`; a `seq` cursor for resume). The dashboard subscribes with `fetch` (so the bearer token travels in the header, never a URL) and re-renders the current view within a second of a transition instead of on a blind 3-second interval; the interval remains as the fallback when the stream is unavailable.
- **Per-tick trace id on every event.** `work_events.correlation_id` existed but nothing ever set it. `tick.sh` now exports one `GAFFER_TICK_ID` per tick; dispatch stamps it on every event written while it is in the environment — the runner's own CLI calls and the agent's MCP writes alike (the `GAFFER_` prefix carries it through the scrubbed agent env), an explicit `DISPATCH_CORRELATION_ID` wins. `dispatch events list --correlation <id>` prints one tick's whole trail (metadata only). The ticket view's event timeline shows a `tick <id>` chip on every correlated event, so the events one tick produced are visible together.
- **Accessibility audit in the browser regression.** `scripts/ui-regression` injects axe-core and runs WCAG 2.1 A/AA over ten rendered views; critical/serious violations fail the run, moderate/minor are reported.
- **Tamper-evident event log.** Every `work_events` row now carries a SHA-256 hash chain (`prev_hash`, `hash`): rewriting, deleting or re-ordering an event after it was written breaks every hash after it. `dispatch events verify` (and a new `dispatch doctor` check) re-derive the chain and name the first broken row. Schema v23 adds the columns and hashes an existing log in insertion order; an export bundle carries the chain and an older bundle is re-chained on import. `/api/health` reports `event_log.chain_ok` and the Health view shows an "Event log" card (intact with the chained count, or BROKEN naming the first bad row), and the Overview's status line reads "event log intact (N events)" or "event log ALTERED at seq N — see Health". The chain proves the log was not altered once written; actor authentication remains a separate concern.
- **`memory history <id>`.** Lists a lore record's earlier versions (newest first) from the `lore_version` snapshots that every `update` writes, with the current row as the head — so an edit is inspectable from the CLI, not only the database.
- **Per-principal API credentials.** `dispatch principal create <name> [--read] [--admin] [--actor-id <id>]` (and `POST /api/principals` from the dashboard's new Settings → Access panel) mints a named bearer token (`gfp_…`, 256-bit, shown once; only its SHA-256 is stored) bound to an actor identity and a capability (`full` or `read`). A request authenticated with it is attributed to that actor on every event and evidence row it writes — the audit trail now says *who* approved, moved or configured, instead of the single `dispatch-api` identity every caller of the shared token shared. `dispatch principal list` / `revoke` and `GET|DELETE /api/principals` manage them (revocation stamps the row; nothing is deleted), `GET /api/whoami` reports how a request authenticated, and `principal.created` / `principal.revoked` land in the tamper-evident event log. Schema v24 adds `api_principals`; credentials are deliberately excluded from the state-export bundle. The shared `DISPATCH_API_TOKEN` and its derived read token are unchanged.
- **OpenAPI 3.1 contract for the REST API.** `GET /api/openapi.json` (read-scoped) and the committed `docs/openapi.json` describe all 109 operations the control plane serves — tickets and their gates, the Factory Map, plan sessions, epics and specs, repositories, runner actions, configuration, read models and the SSE stream — with request bodies and query parameters rendered from the very zod schemas the routes parse with (`packages/dispatch/src/api/openapi/`), each operation's capability (`public` / `read` / `full`) and the error envelope. `scripts/openapi.mjs --check` fails CI when the committed contract is stale, and `api-openapi.test.ts` pins the spec to the router in both directions: every path segment it names must exist in the route source and every route sub-path constant must be documented. Response bodies are described by their TypeScript view type rather than schema'd in this first version.
- **Release pipeline.** Pushing a `vX.Y.Z` tag runs `.github/workflows/release.yml`: it verifies the tag matches the package version, builds and tests the tagged commit, packs the three packages, generates a CycloneDX 1.5 SBOM of every runtime dependency (`scripts/sbom.mjs`, no external tooling), writes `SHA256SUMS` and an in-toto/SLSA v1 provenance statement (`scripts/provenance.mjs`, unsigned — documented), pushes `ghcr.io/tmj-90/gaffer:X.Y.Z` with BuildKit SBOM + provenance attestations and OCI labels, and creates the GitHub release with the changelog section as its notes. `scripts/version.mjs` moves all packages to one version and cuts the changelog; `compose.yaml` honours `GAFFER_IMAGE` to run a published image. `docs/RELEASING.md` documents the flow, verification and limits.
- **Gate replay — golden fixtures for the delivery gates.** `runner/eval/replay.sh` (`gaffer eval replay`) replays eleven recorded deliveries through the real post-delivery gate pipeline — `gaffer_assert_clean_delivery`, `gaffer_diff_stats` + `gaffer_check_minimalism`, `gaffer_run_dod_gates`, `gaffer_run_ac_checks`, in tick order — and compares every verdict, the review flags and the outcome `tick.sh` would take (`submit` / `rework:<gate>`) with each fixture's expectation. Only the dispatch CLI is stubbed (a recorder), so the run needs no model, database or network. Fixtures cover a known-good delivery, a test-breaking one, `node_modules/` + `.crew/` and copied-`src` hygiene leaks, an oversized diff, missing and boilerplate smallest-change notes under both note policies, a failing machine-checkable AC, and a repo with no gate commands under both `GAFFER_ALLOW_NO_DOD` settings. CI runs it on every push (`Gate replay (golden fixtures)`) and prints `results.json`; `runner/test/eval-replay.test.sh` proves the harness fails on an edited expectation and on a weakened gate. `runner/eval/README.md` documents adding a fixture.
- **One-command container run.** A root `Dockerfile` (control plane, runner, CLIs and the Claude Code CLI in one image, non-root, healthchecked) and `compose.yaml` (`docker compose up -d` → dashboard on loopback with the login URL in the logs, state in a volume, repos bind-mounted at `/repos`; a `sandbox` profile builds the per-ticket delivery image and egress proxy). `gaffer dashboard --foreground` runs the server in the calling process with the same action-command wiring as the detached paths, always token-protected, for compose and other supervisors. A `.devcontainer/` for VS Code / Codespaces.
- **Generated configuration reference.** `docs/CONFIG.md` is derived from the code by `scripts/config-reference.mjs`: every `factory.config.sh` and `runner/lib/*.sh` default (grouped by the config's own section banners, lib-defined knobs under their lib, with mode-branch fills distinguished from the real default), whether the dashboard can edit it, which components read it, the Settings-panel-only keys, and every factory-prefixed variable the code reads without ever assigning — the list of knobs that have no default or UI entry, each with the fallback literal found at its read site (two values flag read sites that disagree). CI fails when the committed reference is stale (`--check`).
- **`SANDBOX_PROVIDER` auto-detects the host.** Unset, the runner now picks `sandbox-exec` where the binary exists (macOS) and `docker` where only the Docker CLI does (Linux), instead of defaulting to `sandbox-exec` everywhere and refusing to spawn on every Linux host under strict/required containment. An explicit value still wins. `runner/STRICT_MODE.md` documents the resolution order.
- **Skill selection reads the ticket, not just the stack.** `runner/bin/select-skills.mjs --text` (wired at the delivery site with the ticket title + description) also mounts a skill whose name or description matches the ticket text, so a `dependency-upgrade` or `db-migration` skill reaches the agent for a ticket about that topic even when the repo stack alone would not have selected it. Stack/area matching is unchanged; the text filter is additive.
- **Event-derived cycle time and a real flow efficiency.** `/api/health` takes each ticket's completion time from its last `ticket.transitioned → done` event rather than `updated_at` (which moves on any patch and inflated cycle time or bucketed the ship on the wrong day), and gains `flow_efficiency.median_pct`: the median over shipped tickets of time in active states divided by lead time, from the transition log — `null` until a shipped ticket carries the signal. The Overview reads it; the former client number was a WIP ratio, not flow efficiency.

### Security

- **Autonomy really requires containment now.** `GAFFER_MODE=autonomous` (and `lite`, and every single ship/mutate flag) exported `GAFFER_STRICT_REQUIRE=1` and printed "fails closed without an OS sandbox", but the sandbox was consulted only under `STRICT_MODE=1`, which only `GAFFER_MODE=strict` defaulted on — so the agent launched uncontained. Autonomy now defaults `STRICT_MODE=1` as well, `tick.sh` consults the provider whenever strict is on **or required**, and the worker seam (`runner/lib/worker.sh`) derives and enforces the wrap for **every** spawn site — bootstrap, reviewer, clarify and eval judge were previously never sandboxed even under `STRICT_MODE=1`. A required-but-unavailable sandbox now refuses to spawn (rc 75, no envelope). New test: `runner/test/autonomy-containment.test.sh`.
- **Reviewer ≠ author is enforced server-side.** `approveReview` refuses an `agent` actor whose id equals the agent on the ticket's most recent claim, even when an autonomy flag permits agent approval. The runner's AFK review pass approves as a distinct `<agent>/reviewer` principal. Previously the "agent cannot approve its own work" guarantee rested on the runner's bash hook denying the CLI.
- **Reviewer and clarify agents fail closed on an unwired settings.json.** Only the delivery site verified that the rendered `.claude/settings.json` actually names the `PreToolUse` safety hook; the reviewer and clarify sites wrote the file blind, so a bad template or a full disk could launch them without the deterministic containment boundary. All four spawn sites now go through one installer (`runner/lib/agent-env.sh`: skills mount, verified settings, workspace trust, brief), which removes a half-written or unwired file and refuses the run; the reviewer and clarify sites also used to copy the `CLAUDE.factory.md` brief unguarded and would launch without one.
- **`fast-uri` raised to the patched line.** Four HIGH advisories (GHSA-5jgf-p345-68v8, GHSA-f65p-4m7j-42xc, GHSA-fph4-wmhf-6fwf, GHSA-jqff-g426-hqxp: SSRF and host confusion in URI normalisation) landed against `fast-uri` below 3.1.6, reached through crew's MCP SDK → ajv. The workspace override moves from `^3.1.5` to `^3.1.6` (lockfile resolves 3.1.8); the dependency audit gate is green again.
- **CSP allows no third-party origin.** With the webfonts self-hosted, `style-src` and `font-src` drop the Google Fonts hosts and are `'self'` (plus the inline-style allowance the shell needs). The dashboard's policy now names no external host at all.
- **Notify URLs pass an SSRF policy.** Webhook/Slack sink URLs (env or dashboard settings) must be http(s) and must not target loopback, link-local, unspecified or private-range hosts; refused URLs are skipped loudly and never build a sink. Opt a LAN relay back in with `GAFFER_NOTIFY_ALLOW_PRIVATE=1`. Dashboard settings also now type-check `int`/`boolean` values.
- **Ticket-close lore distillation is gated by default.** The distilled requirement (from the agent-influenceable ticket title + ACs) landed ACTIVE in the factory regardless of the memory gate. It now follows `MEMORY_AUTO_APPROVE` (draft in supervised/lite/graduated; active in autonomous/strict), overridable with `GAFFER_MEMORY_AUTO_PROMOTE`.
- **Drafts stay invisible to delivery agents.** In factory context (`GAFFER_FACTORY=1`) the memory MCP server ignores `search_lore`'s `includeDrafts` flag, the same way it already ignores `includeRestricted` without the env opt-in — a prompt-injected agent could otherwise read another agent's unratified suggestions back into its context.
- **Memory write hygiene on every path.** Envelope-delimiter stripping for the repo digest and feature ledger moved into the memory core, so the CLI path (`memory digest set` / `feature add`, used by crew onboarding and the post-merge rollup) is sanitised like the MCP tools.

### Fixed

- **Settings that were locked or dead: the idle-loop knobs now reach crew, and Dispatch's attempt cap is exported and exposed.** A live audit found `GAFFER_IDLE_MODE` and `GAFFER_IDLE_FEATURE_BACKLOG` in the Settings panel (and exported into every runner child) with no reader anywhere — the panel promised control over the crew idle loops that never happened. Crew's `loadConfig` now applies them as env overrides on top of `crew.yaml`, the way `GAFFER_CREW_EVENTS` overrides the events path: `GAFFER_IDLE_MODE` sets every `loops.idle_*.mode` and `safety.default_idle_loop_mode` (the panel's choices are now crew's real vocabulary — `observe_only` · `create_draft_tickets` · `create_ready_tickets` — with the old short forms still accepted, and an unrecognised value ignored rather than failing open to ready tickets); `GAFFER_IDLE_FEATURE_BACKLOG` flips `loops.idle_feature_backlog.enabled`. `DISPATCH_MAX_ATTEMPTS` — Dispatch's own reject-loop cap, a second attempt cap next to `GAFFER_MAX_DELIVERY_ATTEMPTS` — was read by Dispatch but never set or exported by the runner and absent from the UI; `factory.config.sh` defaults it to the runner's cap so the two agree by construction, exports it, and it is a Settings budget field with its real semantics. `docs/CONFIG.md` regenerated. Tests: `packages/crew/test/idle-loop-env-overrides.test.ts`, `packages/dispatch/test/cost-estimated-spend.test.ts` (settings allow-list), `runner/test/config-reference.test.mjs`.
- **Docker sandbox: per-call roots, the headless-Max token, an honest data mount, and git that works inside.** A live audit of the `docker` provider found: (a) `sandbox_wrap_cmd` wrote the write/read roots to two FIXED files under `$GAFFER_DATA`, so under `GAFFER_CONCURRENCY>1` one worker could overwrite another's roots between composing its wrap and starting its container and be mounted the other's worktree read-write — the files are now per-call (`mktemp`, PID-prefixed) and `tick.sh` sweeps its own on exit; (b) `CLAUDE_CODE_OAUTH_TOKEN` (the `claude setup-token` subscription credential, the documented headless-Max path) matched the `*_TOKEN` deny rule and was not in the keep list, so the scrubbed agent env — host or container — could never authenticate on a Max plan: it is now the one `*_TOKEN` kept, in `gaffer_agent_env` and every `agentChildEnv` (onboard-analyze, decompose, spec-author, product-owner), with look-alike tokens still stripped; (c) the whole `$GAFFER_DATA` was bind-mounted read-write despite the header claiming no canonical DBs were present, and the linked worktree's `.git` pointed into the unmounted real repo so every git command inside failed — the wrapper now states the truth (the MCP data plane writes the canonical SQLite files directly, so their directory must be mounted) and MASKS every other entry in it (settings.json, dashboard-token, the ledgers, other workers' `mcp-runtime` claim tokens, sibling delivery worktrees, `.workers/`), keeping only the DBs and their SQLite siblings, this call's own `--mcp-config`, the crew events log and the safety hook's ledgers visible; the repo's `.git` common dir is mounted read-only with only `objects/`, `refs/`, `logs/` and the worktree's own private dir read-write, and `safe.directory` is set through git's env channel for the uid-mismatched mounts. Tests: `runner/test/sandbox-docker-mounts.test.sh` (new, drives the real wrapper in `GAFFER_SANDBOX_DRY_RUN` mode), `agent-env-scrub.test.sh`, `onboard-analyze.test.mjs`; the CI containment gate `sandbox-docker-containment.test.sh` now also proves DATA_MASKED, OWN_MCP_OK, DB_RW_OK, GIT_STATUS_OK, GIT_COMMIT_OK (round-tripped to the host branch) and GITCONFIG_RO.
- **Runner budgets and caps count spend, see fresh spend, and cover every entry point.** A live audit found five holes in the cost guards: (a) `MAX_TICKS_PER_DAY` was bumped on every non-dry tick including `no_work`, so an idle daemon burned the whole day's cap in ~37 minutes at the defaults and then sat out the day — the counter now advances only for a tick that did (or may have done) paid work (`gaffer_tick_counts_toward_day_cap`; a `no_work` poll is the one exempt result, `error` and a timeout-reaped tick still count) in `loop.sh`, `worker.sh` and the Poll button; (b) `GAFFER_BUDGET_REMAINING` was computed once at process start and exported, so every tick a daemon spawned inherited the stale figure and the router's low-budget downgrade and the `budget_cap` pause never saw new spend — it is recomputed from the ledger every time the config is sourced, an inherited value is overwritten, and the pause guard nets the in-flight delivery's own spend off the headroom; (c) the dashboard's Poll (`bin/poll-once.sh`) bypassed every cap and was never reaped — it now runs the same day/USD gate, wraps the tick in `GAFFER_TICK_OUTER_TIMEOUT` and bumps the counter by the same rule; (d) the parallel worker pool ignored `GAFFER_DAILY_BUDGET_USD` (only the tick-count cap was checked) and the knob was missing from the Settings panel — `worker.sh` honours it and it is a Settings budget field; (e) the dashboard's cost tiles dropped the labelled `estimated_cost_usd` the runner books for a killed/timed-out call while the daemon's day cap counts it, so "Today" could read lower than the figure the factory halted on — the cost and health aggregators now include it (`estimated_usd` / `today_estimated_usd`, shown marked "est."), and the eval judge's model turn, previously unbilled, is booked in the usage ledger (kind `eval-judge`). Tests: `runner/test/day-cap-no-work.test.sh` (real `loop.sh` / `worker.sh` / `poll-once.sh` against a stub tick), `budget-remaining.test.sh` case 8, `day-usd-cap.test.sh`, `eval-judge.test.sh`, `packages/dispatch/test/cost-estimated-spend.test.ts`.
- **Review → merge → memory: the second half of the delivery loop now actually runs.** A live audit found eight defects between "the reviewer approved" and "the factory remembers what shipped": (B9) the runner's unattended AFK merge (`review.sh`) merged and marked done but never ran the post-merge memory work the dashboard merge does — it now calls `merge-ticket.mjs --apply-digest-only` (the same digest-delta apply + feature → shipped step), deletes the merged delivery branch, and logs both; (B10) the prepare-digest-delta skill asked for section names the merge dropped silently (`architecture`, `gotchas`, …) and named a tool that does not exist — the skill now names the four real sections and `record_ac_evidence`, the merge maps the common synonyms, ALWAYS stamps freshness (`digest touch`) even for a `sections: []` delta, and applies the delta to the repo it merged into rather than whatever the agent wrote; (B11) `feature advance … shipped` never ran because no feature id crossed the merge and `feature add --status shipped` created a duplicate row — every ticket of a feature epic now carries `Feature-Id: <id>` in its description, the merge reads it back and advances that exact row, and memory's `addFeature` dedupes by repo + name (never moving a feature backwards); (B12) the reviewer could not record per-AC evidence (its MCP server had no claim token, so every non-human `record_ac_evidence` was refused) — the review pass binds `GAFFER_REVIEW_TICKET` into the reviewer's dispatch server and Dispatch accepts a claimless note for that one `in_review` ticket, never satisfying an AC from it; (B13) a `ready_for_merge` ticket (approve-only AFK, lite mode, a failed auto-merge) could only be "marked merged" without merging — the board offers **Merge now** (`POST /tickets/:id/merge`, 202, fires the merge runner; 409 unless the ticket is actually ready_for_merge) and the human queue lists such tickets as `awaiting_merge`; (B6) the dashboard's "Extend existing" plan sent the target repo as `context.repo`, which the decomposer ignored, so every brownfield plan was decomposed as greenfield and scaffolded a NEW repo — the decomposer lifts it; (B7) the plan-build and spec-author agents spawned from a directory with no `.claude/skills`, so the skill each prompt names was invisible unless the operator had installed skills user-wide — both now run from a throwaway agent home that mounts the factory's skills (same wiring as the product-owner run; the read-only tool denylist is unchanged); (B8) the product-owner run's drafts landed unlinked from the repo (nothing told the agent to pass `repo`, and its hand-rolled MCP render left `${GAFFER_CLAIM_TOKEN}` / `${GAFFER_TICKET_REPOS}` placeholders in the server env), so the run's own guard reported "filed 0 drafts — create_ticket likely denied" and exited 1 — the dispatch MCP now links `GAFFER_DEFAULT_TICKET_REPO` when a caller names no repo, the prompt and skill say to pass it, and the render substitutes every placeholder and fails closed on a leftover. Each fix carries a test derived from the live probe (`runner/test/afk-review-hold.test.sh` case C drives a real AFK ship end to end: merge → digest stamped → feature shipped → branch deleted → reviewer env bound; `packages/dispatch/test/tier2-review-merge.test.ts`; `runner/test/agent-home.test.mjs`).
- **Settings, review hold, clarify isolation, PR creation, access boundary — the confirmed audit defects.** A live audit against the 2026 factory standard found: (B1) saving the Settings page silently turned autonomy OFF — the boolean editors rendered the raw stored value rather than the effective one and the save posted every field; each setting now carries `effective` + `source` (env / file / mode preset / default), editors initialise from `effective`, and the save posts only what the operator changed. (B2) values in settings.json never reached child processes — `factory.config.sh` assigned them but never exported; it now exports, snapshots the operator's real environment at source time so only genuinely env-set keys read as locked, the dashboard applies settings.json and the `GAFFER_MODE` presets to its own environment at startup and after every write, and the launcher unsets config-derived keys before spawning it. (B3) a reviewer that could not run (containment refused, empty envelope) was read as CHANGES and, in AFK mode, reworked a possibly-fine delivery — `review.sh` now records `held` with the reason and never approves or reworks on a non-verdict. (B22) the review and clarify passes resolved the ticket's repo from `repositories[0]` (alphabetically first, so a read-only context repo whose branch does not exist on a multi-repo ticket); they and every former `[0]` site in `tick.sh` now use the primary WRITE repo. (B4) the clarify agent ran in the registered repo with write access — it now runs in a throwaway detached worktree removed on every exit path. (B5) GitHub PR creation could never fire: it ran against the deleted worktree path and passed a flag the CLI does not have; it now targets the real repo and records the PR URL. (B21) a ticket whose repos are ALL read-only fell through to the legacy path and became writable — `tick.sh` detects the empty WRITE set, logs WG-002, releases the delivery and skips the ticket; a ticket with no local repo path is skipped instead of wedging the queue. The reviewer and clarify models are routed (phases `review`, `clarify`). Tests: settings bootstrap/precedence, `afk-review-hold`, `boundary-no-write-repo`, `pr-create-e2e`, `clarify-int-cleanup`.
- **A live refresh could disarm a confirming Approve.** The dashboard skips its live re-render while an approve is armed, but only checked before the render's async fetch; a refresh already in flight when the first Approve click landed swapped in a fresh, unarmed button under the confirming click, which then merely re-armed it. The guard now runs again after the fetch, so an in-flight refresh drops its result instead of replacing an armed control.

- **Dashboard accessibility (found by the new axe audit).** Every form label is now programmatically associated with its control (`for`/`id`) — 42 fields rendered a visually adjacent but unrelated `<label>`, so a screen reader announced an unnamed select or input; a closed bottom sheet was only translated off-screen and its controls stayed in the focus order and accessibility tree (now `visibility: hidden` while closed); the footer text was blended to 3.1:1 by an opacity and now meets 4.5:1.
- **Releasing a runner-held claim retries.** A single failed `runner-release` call used to be final: the claim stayed live until its TTL, the ticket sat `claimed` and a human was paged, usually for a transient (a busy SQLite writer under concurrency, a slow CLI start). The release now makes three attempts with a short back-off and, if all fail, logs the CLI's own error tail instead of a bare "needs a human". Seen once on a macOS CI runner where one of four identical jobs stranded the ticket.
- **Docker sandbox: a symlinked `node_modules` is mounted at the path the link names.** The wrapper mounted the resolved target at its canonical path only; inside the container the worktree's symlink is followed literally, so wherever the two differ (every `/var` path on macOS is really `/private/var`) the link dangled and the DoD gate ran without dependencies. The mount now sits at the link's own path, sourced from the resolved host directory. Found by the first CI run on macOS.
- **Hero image preload only on the Overview.** `index.html` preloaded the Overview hero (200 KB) on every load, so a deep link to a ticket or the review queue fetched an image it never showed and the browser logged an unused-preload warning. The preload is now added at boot only when the Overview is the landing view.
- **UI regression harness.** playwright-core is resolved with CommonJS rules from the harness's own install dir (ESM ignores `NODE_PATH`, so the bare import only worked when the package happened to be in the repo's node_modules); the "Add AC" step targets the AC form's own submit button (a text-only fallback hit the ticket view's "Add repo" button); a dashboard left up by `KEEP_DASHBOARD=1` is stopped before its state is wiped, and the run verifies the server on the port accepts its token instead of 401-ing against a stale one.

- **Post-merge card refresh no longer wipes file summaries.** `gaffer_refresh_cards` re-upserted each changed file without a model summary, and the upsert wrote `tldr = NULL, model_status = 'absent'` — so a repo's file cards decayed to mechanical-only after their first edit. `memory card upsert --keep-model` (new) carries the existing model half forward on a mechanical-only refresh; the refresh uses it.
- **Docker sandbox provider can now run a delivery.** The container mounts `$GAFFER_HOME/packages` and `$GAFFER_HOME/node_modules` (read-only) so the dispatch/memory MCP servers start, follows each worktree's `node_modules` symlinks to their targets so the DoD test gate can run, and invokes the image's own `claude` with a container HOME/PATH instead of the host's binary path. `GAFFER_SANDBOX_DRY_RUN=1` prints the assembled `docker run` argv for testing. The CI containment job fails (rather than skips green) when the gate could not run on a push to `main`.
- **First-run onboarding self-heals.** The dashboard's Onboard button (and `gaffer onboard`) failed with `CONFIG_NOT_FOUND` when `gaffer setup` had not created `crew.yaml`, visible only in the Runs panel while the UI toasted "will appear shortly". `onboard-run.mjs` now initialises the crew config the way setup does, and a tracked run that ends `failed` now raises a toast naming the run and its exit code.
- **Dashboard header at desktop widths**: the brand was a shrinkable flex item, so the tabs squeezed it to its icon and the wordmark overdrew "overview". It no longer shrinks.
- **Docs corrected to match the code**: ARCHITECTURE (no Hono — `node:http`; docker provider is real; no embeddings; Crew MCP is not connected to the delivery agent), README ("memory embeddings"), quickstart/`gaffer dashboard`/RUNBOOK (the token is required for reads too; Node ≥ 22), `.env.example` (not the full knob list; `GAFFER_NOTIFY_REDACT` deprecated), the runtime-migration doc's status line, and the memory README's "default is governed" (now true for the factory too). Retired the obsolete vitest-2 entries from the audit allowlist. Internal trackers moved to `docs/archive/`.

### Changed

- **Crew surface audit.** `docs/crew-surface-audit.md` records which of `packages/crew` the factory actually runs (a static import graph from every runner-invoked entry point): about half is live by default, a quarter is opt-in (idle/maintenance loops, ingest), and ~2,000 lines are reachable only from CLI subcommands nothing calls (`crew run`, `stats`, `repo rescan`, `clarify-capture`, `scan`, `ingest`) or from `crew-mcp`. The decision is written down: the runtime seam files and the TypeScript safety classifier stay (specification and parity oracle), the opt-in loops stay, and the unused subcommands are listed as deletion candidates for a product call rather than removed silently. `packages/crew/02-runtime-architecture.md` no longer lists commands that do not exist.
- **Single runtime for the runner's text processing.** The bash/awk twins behind the typed seams — the prompt and MCP-config renders, the context-primer blocks, the DoD distill/extract/summary/count helpers, the worktree key, the hygiene forbidden-path scan, the minimalism check and the CI-check parse — are deleted along with the `GAFFER_RUNTIME` / `GAFFER_DOD_DISTILL` switches; packages/crew's typed CLIs are the only implementation. Each seam's output is pinned by a golden test (`runner/test/*-golden.test.sh`, fixtures captured from the bash implementations the former parity tests proved byte-identical). Without the crew build a gate fails closed (hygiene reports the unscanned diff as a violation, minimalism returns `check_failed` and the delivery is parked, the CI parse yields no verdict, the renders refuse to launch an agent) and a feedback helper prints nothing — a decision is never invented. `pnpm -r build` is a runtime prerequisite, as it already was for the dispatch CLI.
- **The runner no longer needs python3.** Its ~60 inline python programs (`python3 -c …`, heredocs) and the `jget` one-liner are replaced by `runner/lib/json-tool.mjs`, one node script with a subcommand per former program — ticket selection, the access-boundary partition, the Definition-of-Done command map, the smallest-change note, review feedback, the context-primer renders (pinned byte-for-byte to the checked-in goldens), the eval-judge input and record, the PR body, `gaffer eval`, `status.sh`, `loop.sh`, `run-summary.sh` — and `jget` now takes a JavaScript expression over `d` (`jget 'd.ticket.title'`) instead of Python. Node was already required; the container image's runtime stage drops python3 (the test suite's own assertions still use it, so CI runners and the devcontainer keep it). The prerequisite lists in the README, quickstart and RUNBOOK are updated, and `runner/test/json-tool.test.sh` pins the semantics every call site relies on (a parse or evaluation failure still exits non-zero with no output, so `|| echo <default>` fallbacks are unchanged).

- **Dispatch API auth posture (S-M1)**: every request that returns control-plane data now requires the bearer token — including read-only GET/HEAD on a loopback bind (board, run detail, plan-session transcripts, human queue, cost) — regardless of whether the token was operator-set or auto-provisioned. Only the public bootstrap surface (the static SPA shell + `/healthz`) is served tokenless. This closes the hole where a same-user process (e.g. a token-scrubbed, prompt-injected delivery agent limited to loopback) could `GET /api/tickets` and read the whole backlog. Previously the auto-provisioned dashboard token kept tokenless loopback reads open.
- **Notify redaction is now the default** (security): outbound webhook/Slack bodies are redacted to a minimal body (kind · ticket number · status · dashboard URL) by default, dropping the agent-influenceable ticket `title`/`detail`. Opt into the full body with `GAFFER_NOTIFY_FULL_PAYLOAD=1`. The old opt-in-to-redaction `GAFFER_NOTIFY_REDACT` is deprecated; `GAFFER_NOTIFY_REDACT=0` is still honoured as a full-payload request. Previously the full body was sent by default.
- **Autonomy now requires containment** (security, enforced in code): enabling any agent ship/mutate flag (`DISPATCH_ALLOW_AGENT_APPROVE`, `MERGE_ON_AGENT_REVIEW`, `AUTO_MERGE`, `MEMORY_AUTO_APPROVE`, or `GAFFER_MODE=autonomous`/`strict`) now auto-defaults `GAFFER_STRICT_REQUIRE=1`, so the runner fails closed when no OS sandbox provider is available instead of running unattended with only the deterministic hook. Set `GAFFER_STRICT_REQUIRE=0` explicitly (logged loudly) to opt out when you supply containment out-of-band. Docs also reframe the current OS sandbox as a **write sandbox** — it bounds writes, not reads or network egress.
- **Definition-of-Done gate switches and bounds are documented defaults.** `GAFFER_DOD_TESTS` / `_LINT` / `_TYPECHECK` / `_TYPECHECK_CMD` / `_TIMEOUT` / `_OUTPUT_TAIL`, the rework-history and judge-diff byte bounds, the docker sandbox resource caps and the daemon cadence now have `factory.config.sh` default lines (identical to the consumers' fallbacks, so nothing changes at runtime) and appear in `docs/CONFIG.md` with their meaning.
- **CodeQL and secret scanning in CI.** `.github/workflows/codeql.yml` runs CodeQL (JavaScript/TypeScript, security-and-quality queries) on pushes, pull requests and weekly; `secret-scan.yml` runs gitleaks over the full history on every push and pull request. Both actions are pinned by commit like the rest of the workflows.
- **Coverage floors ratcheted** to the measured level minus a small margin (dispatch 83/85/94/83, memory 78/80/88/78 for lines/branches/functions/statements), so the gains from this cycle's tests cannot silently erode.
- **Transition guards are a declarative capability table.** The eleven near-identical "this edge is legal only through its facade path" if-blocks in `TransitionService.transition()` are one exported `GUARDED_EDGES` table (edge → legalising flags → message → why) and a single check. Behaviour and messages are unchanged; adding a guarded edge is a row, and the table is unit-tested edge by edge.
- **Runner worktree plumbing de-duplicated.** The node_modules symlink loop `tick.sh` carried three times (resume, fresh worktree, rework re-add) is one helper, `gaffer_link_node_modules`, with its own test.
- **`lima` sandbox provider stub removed.** It was offered in the Settings dropdown and the provider seam but never contained anything; an unimplemented provider is now simply an unknown one (fails closed under `GAFFER_STRICT_REQUIRE=1`, warns and degrades otherwise). `docs/vm-sandbox-provider.md` is renamed `docs/docker-sandbox-provider.md`: docker is the shipped provider, the microVM section is a design sketch.
- **One onboarding path.** `runner/GETTING_STARTED.md` (the older by-hand walkthrough, which repeated `quickstart.md` §1–3 and still called containment macOS-only) is removed; the root `quickstart.md` is the canonical first run, `runner/RUNBOOK.md` the full reference. The RUNBOOK prerequisites name both sandbox providers.
- **Dead code removed.** Dispatch: the never-written `external_refs` table is dropped (schema v22; the migration removes it from existing databases and the state-export bundle no longer lists it), and the write-only `isOperatorSetToken` / `isPrivilegedPath` / `recordApiTokenSource` auth leftovers are gone — the token decision has been uniform since S-M1 and nothing read them. Memory: the package-local `.github/workflows/ci.yml` and `dependabot.yml`, which GitHub never runs from a sub-directory, are removed (the root workflow covers the package).
- **Dispatch bouncing-tickets query**: the cross-ticket rework signal (`bouncingTickets`) now computes the per-ticket gate breakdown, ranking, and limit in a single SQL statement instead of one query per candidate ticket with the limit applied after enrichment. Behaviour unchanged.

## [0.1.0] - 2026-06-17

### Added

Initial public release of Gaffer — a local-first, supervised software factory.

**Dispatch** (`packages/dispatch`) — the control plane. Manages tickets, epics, scopes, and per-repo access. Exposes a REST API, an MCP server, a web dashboard, and a CLI. Enforces the server-side review/merge gate: by default, an agent actor cannot approve or merge its own work.

**Crew** (`packages/crew`) — the factory runtime. An MCP tool server that exposes factory-level tools to Claude agents, plus a hooks engine and idle loops for drafting work, ingesting issues, and repo onboarding.

**Memory** (`packages/memory`) — durable, human-gated knowledge. A knowledge base (lore) plus the Repo Understanding engine: Repo Digest, feature ledger, and grounded lore drafts. Seeded at onboarding; refreshed as tickets merge. Also usable standalone as `memory-mcp`.

**Runner** (`runner/`) — the bash orchestrator. Spawns a `claude -p` agent per ticket with a 66-skill library. Includes a deterministic PreToolUse safety hook (`safety-hook.mjs`) that scopes writes to the per-ticket git worktree and fails closed. Model tiering: planning on a strong model, implementation on a fast one. Per-call resource caps (wall-clock timeout + agent turn cap).

**Web dashboard** — seven views: Overview, Work, Review, Epics, Map, Memory, Settings. Review is the human gate where tickets wait for approval before any merge occurs.

**Safety boundary** — worktree isolation (every ticket in a throwaway git worktree), deterministic regex-based safety hook, server-side human review gate. Autonomy flags (`DISPATCH_ALLOW_AGENT_APPROVE`, `MERGE_ON_AGENT_REVIEW`, `MEMORY_AUTO_APPROVE`) are opt-in and off by default.
